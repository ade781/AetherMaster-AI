
PLAN PERBAIKAN, PENINGKATAN, DAN DATABASE REFACTOR

SCOPE
-----
Rencana ini adalah lanjutan dari improvement sebelumnya. Fokusnya bukan mengulang pekerjaan yang sudah benar, tetapi mengaudit implementasi saat ini lalu melakukan perbaikan yang masih diperlukan.

Fokus:
1. Audit UI yang sudah diimplementasikan.
2. Audit seluruh data hardcoded di server.
3. Memindahkan data dunia seperti Item, NPC, Campaign, Location, Quest, dan World Fact ke database.
4. Melakukan perombakan database secara menyeluruh dan terstruktur.
5. Menjadikan database sebagai sumber data dunia.
6. Menjadikan Game State Engine sebagai sumber kebenaran state permainan.
7. Menjadikan Gemini sebagai narrative engine, bukan sumber kebenaran game state.
8. Memastikan UI membaca state dari backend.
9. Memperbaiki save/load, story timeline, dan rewind.
10. Mempertahankan gameplay yang sudah ada.
11. COMBAT SEPENUHNYA DI LUAR SCOPE.

PHASE 5 - GAME STATE ENGINE
============================================================

Buat/refactor Game State Engine sebagai sumber kebenaran.

Engine menangani:
- HP
- Mana
- Gold
- Inventory
- Item consumption
- Quest state
- World facts
- Reputation jika digunakan
- Story progression
- Location state
- Save state
- Rewind state

Gemini tidak boleh langsung mengubah database.

Flow:

Gemini Proposal
    ->
Validation
    ->
Game State Engine
    ->
Database

Contoh:
AI mengusulkan receivedItemId.

Engine harus:
1. mencari item di database
2. memastikan item valid
3. memeriksa apakah reward valid
4. mengubah inventory
5. menyimpan state

Valid JSON tidak berarti valid game state.
